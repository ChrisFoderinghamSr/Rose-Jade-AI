# Architecture

Browser UI → Next.js route → origin/session/ownership checks → validated service operation → SQLite or configured provider → refreshed UI.

apps/web provides the web application, authentication and consolidated backend. packages/core/src/db.mjs defines SQLite tables, defaults and first-run owner setup. api.mjs handles validated operations; exports.mjs generates files; billing.mjs owns PayPal operations. packages/security/src/access.mjs handles scrypt, hashed sessions, role/ownership checks, rate limits and bounded inputs. packages/ai/src/provider.mjs controls model requests and context selection.

The modular repository is preserved; older empty package folders remain future integration boundaries. No separate API/admin service is required to run the current app.

## Data boundaries

Every private record is keyed to a user ID. IDs from the browser are checked with that owner before reads/updates/deletes/downloads. Public portfolio output explicitly projects only approved title, summary and HTTPS link; it includes no user IDs, email, private messages or memory. The portfolio widget is read-only and does not share the user's private assistant.

Memory is Pending/Approved/Rejected and can be deleted. Explicit “remember” cues create proposals. No hidden psychological scoring, autonomous training or model-weight changes occur. Local demo templates transparently illustrate workflows; actual models are separately configured. Quoted memory/documents are treated as context rather than privileged instructions, and models have no tool execution privileges.

SQLite uses WAL and foreign keys, parameterized queries and transactional privacy erasure/billing updates. Sessions contain random tokens; only token hashes are stored. Private runtime state sits in .local (or ROSE_DATA_DIR), excluded from Git, Docker input and tracing. One persistent server/volume is expected; ephemeral serverless disk is unsuitable.

Model output is escaped text. Generated HTML/code is downloaded as an attachment, never evaluated. PDF/DOCX are generated by maintained libraries. PDF fonts are basic Latin-1; editable DOCX and text retain Unicode. MIME email exports are inert until a user imports/sends them. SMTP uses a separate explicit send flow and server recipient allowlist.
