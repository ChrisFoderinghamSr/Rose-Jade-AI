# Security — cloud-only revision

Implemented: per-account ownership checks; salted scrypt passwords; revocable hashed eight-hour sessions; HttpOnly/SameSite cookies; same-origin writes; asynchronous parameterized PostgreSQL; atomic quota increments and conditional record revisions; transaction-scoped cloud operations; reviewed SMTP actions; no model execution tools; explicit cloud/microphone consent; PayPal provider-side signature verification and subscription reconciliation.

Aurora Data API and Secrets Manager use the hosting compute role. Limit IAM to the specific cluster/secrets, use HTTPS and secure cookies, configure backups and recovery, and use database roles/secret policies appropriate to production. Application code never writes local credentials or silently falls back to disk storage. Source/build tracing and Git ignore rules exclude historical private data. The old local .local folder is not deleted or uploaded by the migration.

This remains an initial working app. Email verification, MFA/SSO, automated password recovery, full account deletion, distributed edge/WAF controls, provider budgets, immutable audits, mature migrations, large-dataset pagination and operational monitoring require further work before a broad paid launch. Request limits do not replace proxy streaming limits. The database contains personal data; administrators and their access policies must be trusted. Model text is not a guarantee of safety, legal correctness or outcomes.

Public viewing/registration is closed unless explicitly enabled with PUBLIC_ACCESS_UNTIL. Unauthenticated visitors have no AI endpoint. Private sessions can continue after public access expires. Never enter real provider credentials into chat, Git or frontend configuration. Sandbox payment/SMTP/model acceptance testing with your actual cloud settings has not been performed by mocked tests.
